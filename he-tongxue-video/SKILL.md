# 何同学风格视频脚本生成器

## 触发条件

满足以下任一条件时自动启用：

- 用户提到"生成视频脚本"、"写脚本"、"视频文稿"
- 用户给出"想法.md"或类似选题文件，要求产出
- 用户指定"何同学风格"或类似自媒体报道人风格
- 当前工作目录是某个视频选题文件夹（含"想法"类文件）

## 核心工作流

### Step 1：定位选题文件

- 在当前工作目录（或用户指定目录）下查找 `想法.md` / `选题.md` / `topic.md` 等
- 若未找到，向用户询问选题文件路径
- 读取选题文件，提取：
  - **主题**：视频核心话题
  - **对比项 / 内容大纲**：视频要覆盖的对比点
  - **目标受众**：写给谁看
  - **核心立场**：作者倾向（如有）
  - **风格要求**：风格定位
  - **数据来源 / 引用链接**（如有）

### Step 2：确定视频结构

根据内容密度，建议时长 **15-20 分钟**（约 3500-5000 字旁白）：

```
开场（1.5-2 分钟）→ 用具体生活场景作为钩子
主体（12-15 分钟）→ 分 3-5 个章节对比
结尾（2-3 分钟） → 个人立场 + 选择建议 + 金句升华
```

### Step 3：生成《视频文稿.md》

**输出路径**：`[选题文件夹]/视频文稿.md`

**内容要求**：
- 第一人称叙述（"我"为主线）
- 用具体数字 / 时间锚定（不要"很快"，要"30 秒"）
- 真实生活场景代入（"上周我跟朋友一起坐地铁"）
- 承认对方优点，不绝对化
- 表格对比 + 引用链接
- 结尾金句升华

**何同学风格要素**：

| 维度 | 怎么做 |
| --- | --- |
| 开场 | "你有过这种经历吗？" + 具体场景 |
| 引入 | "我当时就..." / "后来我查了一下..." |
| 对比 | 表格 + 数字 + 时间 |
| 转折 | "但是！" / "结果..." |
| 立场 | "如果你问我，我个人选 X" |
| 收尾 | "最后一句话，是我很喜欢的一个观点：'……'" |

### Step 4：生成《视频脚本.md》

**输出路径**：`[选题文件夹]/视频脚本.md`

**内容要求**：

#### 4.1 基本信息表
- 时长、风格、拍摄比例、帧率、收音方式

#### 4.2 设备清单
- 相机、镜头、灯光、稳定器
- 道具（涉及的产品、对比物）
- 后期软件

#### 4.3 拍摄场地
- 外景 vs 室内
- 真实场景 vs 模拟场景

#### 4.4 场景分镜（30-50 个 SCENE）
每个 SCENE 必须包含：
- **时间码**：精确到秒
- **景别 / 运动**：特 / 近 / 中 / 全 + 固 / 推 / 拉 / 摇 / 移 / 跟
- **场景**：拍摄地点
- **画面描述**：具体动作、机位、构图
- **旁白**：该场景主持人说的话
- **字幕**：屏幕文字特效
- **B-roll**：补充画面
- **音效 / BGM**：背景音乐
- **转场**：硬切 / 溶解 / 淡入淡出
- **时长**：大致秒数
- **备注**：拍摄注意事项（可选）

#### 4.5 后期制作要点
- 调色方向
- 字幕样式（字体、颜色、关键词高亮）
- BGM 数量与风格
- 音效使用规范
- 动画 / 动效

#### 4.6 拍摄排期
- 按天划分
- 场景 / 任务对应

#### 4.7 风险与备选方案
- 列出可能翻车的点
- 每个风险给出备选方案

### Step 5：自检清单

生成完毕后，对照检查：

- [ ] 视频文稿与视频脚本的场景数量是否一致
- [ ] 所有数字 / 时间是否在两份文件中保持一致
- [ ] 是否每个 SCENE 都有完整的 9 个要素
- [ ] 是否在文末附上数据来源
- [ ] 是否在脚本中标注了重点场景

## 何同学风格速查表

### 标志性句式

- "你有过这种经历吗？"
- "我当时就..."
- "后来我查了一下..."
- "这个事我不能 100% 确定是真的，但如果你有兴趣，可以试试"
- "如果你问我，我个人选 X"
- "最后一句话，是我很喜欢的一个观点："

### 标志性结构

1. **具体场景开场**（不是直接抛问题）
2. **真实经历 / 数据**（不靠"听说"）
3. **承认对方优点**（"iPhone 不是完美的，它的缺点是真实的……但是它的优点也是真实的"）
4. **数字 + 时间双锚定**（"30 分钟 / 8999 元"）
5. **结尾引用类金句**（"没有最好的手机，只有最适合你的手机"）

### 避免的写法

- ❌ "众所周知" / "大家都知道" / "毫无疑问"
- ❌ 堆参数不解释（"8GB RAM" 但不说用起来怎样）
- ❌ 拉一踩一（必须双方各给一段认可）
- ❌ 抽象描述（"很流畅" / "很快" / "很不错"）
- ❌ 工具书式结尾（"以上就是本期内容"）

## 输出文件命名规范

| 文件 | 用途 | 受众 |
| --- | --- | --- |
| `视频文稿.md` | 旁白文字 | 主持人录音 |
| `视频脚本.md` | 分镜表 | 摄影师 / 剪辑师 |

## 默认参数（可在调用时覆盖）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 时长 | 18 分钟 | 约 4500 字旁白 |
| 场景数 | 35-40 个 | 含 5-7 个重点场景 |
| 章节数 | 4-5 章 | 主体部分 |
| 重点场景数 | 5-7 个 | 建议重点打磨 |
| 总拍摄日 | 5 天 | 含机动 |

## 调用示例

用户输入示例：
- "我有一个视频选题文件夹，帮我写脚本"
- "用何同学风格生成视频"
- "读取 想法.md 生成视频文稿和视频脚本"

## 失败回退

- 若 `想法.md` 缺失：询问用户选题文件路径
- 若选题文件内容过少：询问补充信息（主题、对比项、立场）
- 若用户未指定风格：默认采用"何同学风格"，并在脚本中标注
- 若选题是非对比类：退化为单一主题结构（开场 / 主体 / 结尾 三段式），仍保留何同学文风

## 依赖

- 无外部工具依赖
- 输入：选题文件（Markdown / 纯文本）
- 输出：两个 Markdown 文件
